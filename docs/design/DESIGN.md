## 0. Коротко

**Что строим.** Цепочка «устройство на машине → сервер → ПК и телефон». Она показывает моточасы,
пробег и местоположение спецтехники и на этой основе ведёт замену масла и ТО с продуктами FUCHS
для трёх ролей: FUCHS, дистрибьютор, конечный клиент.

**Пять главных решений.**

1. **Не «каждая модель машины», а 9 классов интеграции (A–I).** Любая машина при осмотре попадает
   в один из них; модель машины становится записью в справочнике, а не отдельной разработкой.
   Только так реально охватить «любую технику в поле, лесу и карьере».
2. **Устройство на старте — серийный российский трекер с CAN** (Galileosky 10 Plus или
   Навтелеком SIGNAL) плюс бесконтактный CAN-считыватель (CAN-LOG B44) там, где шина проприетарная.
   Собственное устройство — этап 2, если объёмы оправдают разработку и сертификацию.
3. **Шлюз устройств — Traccar (open-source, Apache-2.0)**, ядро (нормализация, учёт моточасов,
   ТО, роли, уведомления) — собственное. Traccar уже декодирует протоколы российских трекеров;
   на стенде найдены три его реальные ловушки, для каждой есть решение (раздел 6.3).
4. **Хостинг в РФ** (152-ФЗ, ст. 18 ч. 5 [S7]): российское облако; Cloudflare и Vercel —
   только для публичных материалов без персональных данных.
5. **Моточасы — главная величина.** Пробег показываем только там, где он физически осмыслен
   (колёсная техника); для гусеничной и медленной техники GNSS-пробег недостоверен [модель].

**Что доказано в этой среде** (без выезда к машине):

- контрольные суммы и разбор протоколов совпадают с пакетами реальных устройств:
  Galileosky 12/12, EGTS 17/17, Wialon IPS 5/6 плюс два официальных примера Gurtam [подтверждено];
- сквозной прогон: 17 428 записей от 7 классов машин по 3 протоколам прошли через реальный
  Traccar 6.15.3 и нормализацию; после сверки 100 % записей совпали с отправленными [подтверждено, стенд];
- численные выводы о точности способов подсчёта моточасов и пробега и о задержках связи [модель].

**Что здесь доказать нельзя** и что делается на следующем этапе: работа на конкретной машине
(доступ к CAN, программа считывателя, монтаж, реальное покрытие сети). Для этого предусмотрены
стенд квалификации устройств и пилот на 20–50 машинах (раздел 9).

## 1. ТЗ «по полочкам»

| Пункт ТЗ | Что это значит на практике | Что нужно решить |
|---|---|---|
| 1. Устройство, собирающее моточасы, пробег и местоположение с машины в поле, лесу, карьере | **Моточасы** — время работы двигателя; по ним меняют масло. **Пробег** — км, имеет смысл для колёсной техники. **Местоположение** — GNSS ГЛОНАСС+GPS | Откуда брать моточасы на разных машинах (CAN, D+, напряжение); как работать без связи; свой или серийный прибор |
| 2. ПО для ПК и телефона | Сервер + веб-кабинет (ПК) + приложения iOS/Android | Стек, карты, push, публикация (RuStore) |
| 3. ПО для FUCHS, дистрибьюторов, конечных потребителей | Многоуровневый доступ: FUCHS → дистрибьютор → клиент | Кто что видит, согласия клиента, чьи это данные |

### 1.1 Зачем это FUCHS (гипотеза, требует подтверждения)

Масло и смазки меняют по моточасам (или по км и календарю — что наступит раньше). Кто знает
моточасы машины, тот знает, **когда и какой продукт** понадобится клиенту. Отсюда ценность:

| Роль | Что получает |
|---|---|
| Клиент | Карта парка, моточасы, пробег, напоминания о ТО, журнал замен, заказ масла в два нажатия |
| Дистрибьютор | Список «кому через 7/14/30 дней нужна замена и сколько литров», заказы, сервис |
| FUCHS | Прогноз спроса по продуктам и регионам, работа дистрибьюторов, программы лояльности/гарантии |

Напоминания о ТО по моточасам есть во многих телематических платформах [допущение]; отличие
этого продукта — связка «данные машины → рекомендация продукта FUCHS → дистрибьютор → поставка».

Контекст FUCHS в РФ: ООО «ФУКС ОЙЛ» (ОГРН 1027600839078) действует [S29]; по отраслевой прессе
FUCHS сохранил производство смазочных материалов в России [S28]. Юрлицо-заказчик и владелец
данных — вопрос №1 (раздел 11).

## 3. Как взять данные с любой машины: 9 классов интеграции

| Код | Класс | Моточасы | Пробег | Что ставим |
|---|---|---|---|---|
| A | J1939, двигатель сам транслирует моточасы | CAN, SPN 247, шаг 0,05 ч | CAN (SPN 245/917) или GNSS | Трекер с CAN, считывание без передачи в шину |
| B | J1939, моточасы только по запросу | Трекер шлёт запрос PGN 59904, ЭБУ отвечает PGN 65253 | как A | Трекер с активными запросами |
| C | ISOBUS (тракторы и орудия) | Через трактор (те же PGN J1939) | — | Трекер на тракторе; орудия без ДВС отдельно не подключаем |
| D | Проприетарный CAN | Через считыватель с программой модели | через считыватель | CAN-LOG B44 + трекер |
| E | Нет CAN (механический двигатель) | D+ генератора или порог напряжения + стартовое показание счётчика | GNSS | Трекер с дискретными входами |
| F | Облако производителя | Из API OEM (РСМ Агротроник, ИТИС-КАМАЗ, Кировец-Агромонитор, облака SANY/XCMG, ISO 15143-3) | из API | Договор с OEM |
| G | Файлы StanForD 2010 (лес) | Из файлов бортового компьютера [проверить состав] | — | Процедура выгрузки |
| H | На машине уже есть чужой трекер | Параметр трекера | параметр | Ретрансляция EGTS/Wialon на наш шлюз, без монтажа |
| I | Трекера нет | Фото счётчика + ввод в приложении | фото одометра | Только приложение, QR-код на машине |

Полная таблица классов машин (≈26 строк: поле, лес, карьер, стройка, дорога) с представительными
моделями, двигателями и уверенностью — лист «Классы_машин» в Excel. Важно: класс определяется
**экземпляром** (двигатель, год, модификация), а не маркой. Например, у МТЗ-82.1 с Д-243
CAN нет (класс E), а у Кировца К-7М электронный двигатель с J1939 (класс A) [S15, S33].

### 3.1 «Пришёл человек с харвестером» — что происходит дальше

1. **Регистрация машины** в мобильном приложении: марка, модель, год, VIN/PIN, фото шильдика
   и фото счётчика моточасов на приборной панели (стартовое значение).
2. **Классификация.** Справочник предлагает класс (для харвестера — A или B) и чек-лист осмотра:
   есть ли ЭБУ двигателя, где проходит CAN J1939, есть ли диагностический разъём.
3. **Подбор комплекта:** трекер с CAN и большим архивом; для машин класса D — CAN-LOG B44;
   для класса E — провод к D+; выносная антенна на крышу кабины.
4. **Монтаж** (оценка 1–3 ч [допущение]). Мастер монтажа в приложении проверяет автоматически:
   есть связь; есть фиксация GNSS; CAN-кадры идут; моточасы по CAN совпадают со счётчиком на
   панели (±0,1 ч); «двигатель выключен → включён» распознаётся; для класса E порог напряжения
   соответствует бортсети 12/24 В. Ошибка порога даёт +70,7 % к моточасам [модель].
5. **Привязка**: клиент, дистрибьютор, согласия на доступ.
6. **План ТО**: узлы (двигатель, гидравлика, трансмиссия, мосты, пильный агрегат), объёмы,
   интервалы, продукты FUCHS — из справочника с указанием источника (руководство OEM, рекомендация FUCHS).
7. **Эксплуатация**: данные идут в кабинет; прогноз даты замены; уведомления клиенту и
   дистрибьютору; заказ масла; отметка о замене механиком (QR на машине, фото, литры).
8. **Контроль качества**: периодическая сверка со счётчиком (фото); тревоги «моточасы не растут
   при работе», «нет связи больше N дней», «моточасы уменьшились».

Особенность леса: на лесосеке связи часто нет [модель: у харвестера 0 % времени онлайн при
покрытии только у волока]. Данные копятся в архиве трекера (170 000 точек у Galileosky 10 Plus
[S9] — это около 500 суток работы харвестера [модель]) и уходят при выезде к зоне покрытия.
Для моточасов и ТО это приемлемо; «живая» карта для такой машины физически невозможна без спутника.

## 4. Физика данных: что показал стенд

### 4.1 Моточасы

| Способ | Как работает | Ошибка [модель, 7 суток] | Вывод |
|---|---|---|---|
| CAN, SPN 247 (PGN 65253) | Счётчик ЭБУ, тот же, что на панели; шаг 0,05 ч [S5] | ≤ 0,066 ч (шаг + период опроса) | Основной способ |
| D+ генератора | Сигнал «генератор возбуждён» = двигатель работает | −0,02…−0,03 % | Лучший без CAN |
| Порог напряжения бортсети | Напряжение выше порога при работе генератора | −0,02…−0,06 % при верном пороге; **+70,7 %** при пороге для 12 В на 24-вольтовой машине | Только с автопроверкой при монтаже |
| Зажигание | Время включённого зажигания | **+4,7…+5,7 %** (+23…+28 ч на интервал 500 ч) | Крайний случай |

Важные детали J1939 (таблица параметров — лист «J1939_параметры»):

- Сообщение с моточасами (PGN 65253) по J1939-71 передаётся **по запросу** [S3, S4]. Если ЭБУ
  его не транслирует, трекер должен послать запрос PGN 59904 и стать активным участником шины.
  Без запроса у харвестера в модели 0 % записей с моточасами, с запросом значения есть [модель].
  Активный опрос требует согласия владельца машины (вопрос №13).
- Значения `0xFE…` означают «ошибка», `0xFF…` — «нет данных». Это не числа: в платформе они
  хранятся как отсутствие значения, иначе появятся «214 миллионов моточасов» [подтверждено тестами].
- В записи с реального грузовика публичным J1939 DBC декодируется 85 из 142 CAN-идентификаторов,
  остальные проприетарные [S3]. Отсюда нужда в считывателях с базой моделей (класс D).

**Сверка со счётчиком.** Для классов E и I моточасы трекера = стартовое показание + наработка.
Раз в N недель механик фотографирует счётчик, и система корректирует расхождение с журналом.
При замене ЭБУ или трекера вводится новое смещение с фото.

| Трактор (J1939) | 833,4 | 941,2 | 837,5 | 833,0 | — |
| Трактор без CAN | 660,3 | 789,1 | 663,7 | 661,1 | — |
| Харвестер | 31,5 | 795,0 | 13,9 | 38,4 | — |
| Форвардер | 172,7 | 851,1 | 210,4 | 181,5 | — |

Выводы:

1. Для колёсной техники на открытом небе пробег по точкам трека точен (±0,1 %). CAN-одометр
   даёт систематический сдвиг от износа и размера шин (в модели заложено +1,5…2 %).
2. У экскаватора наивное суммирование GPS даёт 434 км при истинных 0,98 км: антенна на поворотной
   кабине описывает дугу плюс шум приёмника. **Пробег для гусеничной и стационарной техники не показываем.**
3. Единого порога скорости нет: для медленного харвестера порог 1,5 км/ч даёт ×2,9, порог 3 км/ч
   даёт −53 %; для форвардера лучший порог 5 км/ч (+0,5 %) [модель, лист «Сим_варианты»].
   Настройки пробега задаются профилем класса машины.

### 4.3 Местоположение

GNSS ГЛОНАСС+GPS, антенна на крыше кабины. Под пологом леса точность типичных приёмников на
харвестерах — от единиц до десятков метров [литература: Riekki & Ovaskainen, *Forests*, 2022;
Huang et al., *Forests*, 2022]; в модели σ = 4 м с выбросами многолучевости до 20 м.
В интерфейсе рядом с точкой всегда показывается её возраст.

### 4.4 Связь и задержка

| Машина [модель] | Онлайн | Задержка p95 / макс | Суток до заполнения архива 170 000 |
|---|---|---|---|
| Трактор, карьер | 91–99 % | ≤ 0,06 ч / ≤ 0,5 ч | 88–570 |
| Форвардер | 23 % | 4,8 ч / 28,9 ч | 192 |
| Лесовоз | 43 % | 6,8 ч / 36,2 ч | 119 |

Узкое место — не объём архива, а задержка. Варианты для леса: принять задержку (для ТО достаточно);
спутниковый канал для критичных машин [проверить доступность услуг]; выгрузка архива через телефон
по Bluetooth [проверить у модели трекера].

Сети: 3G операторы отключают (МТС ускоряет отключение в 2026 [S21]); 2G сохраняется не менее
10 лет [S22]. Требование к модему — LTE Cat.1/Cat.4 с резервом 2G.

Трафик одной машины: 0,5–3,8 МБ/мес по протоколу Galileosky, 1,4–10,9 МБ/мес по Wialon IPS,
0,75–5,2 МБ/мес по EGTS [модель + закодированные пакеты]. Калькулятор — лист «Трафик_расчёт».

### 5.1 Купить или разработать

| Критерий | Серийный трекер (этап 1) | Собственное устройство (этап 2) |
|---|---|---|
| Срок до пилота | недели | 9–15 месяцев [допущение] |
| Сертификация | у производителя (EAC) | своя: ТР ТС 020/2011 (ЭМС) и связь [проверить объём] |
| Риск | низкий, отработано на тысячах машин | высокий: железо, прошивка, поставки компонентов |
| Стоимость единицы | ориентир 8,5–18 тыс. ₽ [S9, S10] | зависит от тиража, нужны КП |
| Контроль функций | в пределах настроек прибора | полный |

**Рекомендация:** пилот и первые сотни машин — серийные трекеры российского производства
(Galileosky 10 Plus как основной кандидат: CAN J1939/FMS, архив 170 000 точек, BT 5.0 [S9];
Навтелеком SIGNAL S-2653 как второй [S10]) плюс CAN-LOG B44 для проприетарных шин [S12].
Teltonika не закладывать: поставки в РФ прекращены в 2022 [S13]. Вопрос брендирования («устройство
FUCHS») решается корпусом/прошивкой производителя по договору, без собственной разработки [проверить].

### 5.2 Требования к устройству

- GNSS ГЛОНАСС+GPS (желательно также BeiDou/Galileo), выносная антенна.
- CAN J1939: пассивное чтение и **активные запросы** PGN 59904; второй CAN или вход считывателя.
- Дискретные входы: зажигание, **D+**; аналоговый вход; питание 9–36 В с защитой от бросков бортсети.
- Архив не меньше 100 000 точек с отправкой по принципу «сначала старые» (FIFO).
- Модем LTE Cat.1/Cat.4 + 2G; Bluetooth для настройки и, желательно, выгрузки архива.
- Защита не ниже IP65 [допущение]; −40…+85 °C.
- Протокол на сервер: Galileosky, Wialon IPS 2.0 или EGTS (все три проверены на стенде).
- Удалённая настройка и обновление прошивки; уникальные учётные данные на каждое устройство.

### 5.3 Если делать своё устройство (этап 2)

Состав: микроконтроллер, модем LTE Cat.1 с GNSS или отдельный GNSS-модуль, два CAN-трансивера,
входы с защитой, аккумулятор, flash на 2 млн+ точек, BLE. Проектные нормы по электропитанию
автомобильного класса и ЭМС, сертификация ЕАЭС — оценить со специализированной лабораторией
[проверить]. Протокол — стандартный (Wialon IPS или EGTS), тогда серверная часть не меняется.

### 6.3 Три ловушки Traccar, найденные на стенде, и решения

1. **`database.saveOriginal=true` ломает чёрный ящик Wialon.** В атрибуты каждой точки пишется весь
   сырой пакет; пакет на 100 сообщений — около 37 000 символов, а колонка `attributes` ограничена
   4000. Итог прогона: 7013 точек не сохранены. **Решение:** `saveOriginal=false`, сырые пакеты
   архивировать из протокольного журнала. [подтверждено, стенд]
2. **Пересылка по HTTP теряет точки при медленном приёмнике.** В прогоне пересылкой пришло
   13 860 из 17 427 (79,5 %). По исходникам `PositionForwardingHandler`: при повторе устройство
   ищется в кэше; после разрыва TCP-сессии оно выгружено, отправка падает с NullPointerException,
   точка списывается. **Решение:** приёмник отвечает мгновенно (запись пачками в фоне), пересылка
   через локальный брокер, ежедневная сверка с БД шлюза. Сверка на стенде восстановила 100 %.
   [подтверждено, стенд + исходный код]
3. **EGTS теряет моточасы.** Декодер Traccar 6.15.3 разбирает координаты, но пропускает подзаписи
   счётчиков `COUNTERS_DATA`/`ABS_CNTR_DATA`: в пакетах моточасы были в 3796 записях, после Traccar
   — в 0. **Решение:** доработать декодер (патч на Java) или принимать EGTS своим приёмником;
   эталонный декодер счётчиков уже есть в `sim/protocols/egts.py`. [подтверждено, стенд]

Мелкие особенности: теги CAN_B0/B1 Galileosky Traccar отдаёт «сырыми» — масштаб задаёт профиль
устройства; имена параметров Wialon приводятся к нижнему регистру; в EGTS номер пакета читается
как big-endian, а HDOP не масштабируется. Один реальный пакет логина Wialon пришёл с нестандартной
CRC, поэтому ошибку CRC логина нужно журналировать, а не отбрасывать пакет.

### 6.4 Нормализация и профили устройств

Профиль устройства — **данные, а не код**: «атрибут шлюза → поле платформы, масштаб, единица».
Пример: для Galileosky в режиме FMS `canB1 × 0,05 = моточасы` — это **гипотеза H-GS-1** (закрыта в v2: по официальному протоколу моточасы FMS передаются в теге 0xDB, значение / 100 = ч; см. DESIGN-v2.md §7):
публичного описания тегов CAN_B0/B1 не нашлось. Косвенные признаки: руководство перечисляет
данные режима FMS в порядке «общий расход топлива, уровень, температура, обороты, общий пробег,
моточасы», и Traccar применяет к соседним тегам «сырые» масштабы J1939. До пилота гипотеза
проверяется на стенде квалификации: генератор CAN (этот репозиторий + USB-CAN адаптер) подаёт
известные значения в трекер и сверяет, что приходит на сервер.
По руководству пользователя Galileosky этим тегам можно назначить нужный CAN-параметр
в конфигураторе [проверить на приборе]. Тогда смысл тега задаётся нашей конфигурацией
устройства и фиксируется в профиле вместе с версией прошивки.

Правила качества данных применяются **в порядке времени фиксации, а не прихода**: на стенде
пересылка шлюза шла не по порядку, и проверка «моточасы уменьшились» по порядку прихода давала
ложные срабатывания [подтверждено, стенд]. Правила: моточасы не убывают (кроме оформленной замены
ЭБУ); прирост моточасов не превышает прошедшего времени; точки без фиксации GNSS не меняют
местоположение; дубликаты по ключу «устройство + время» отбрасываются.

### 6.5 Журнал моточасов («одна правда»)

Для каждой машины хранится журнал: источник (CAN/D+/напряжение/зажигание/ручной ввод/API OEM),
приоритет источника, смещения при монтаже и замене оборудования, сверки со счётчиком с фото.
Отображаемое значение берётся из лучшего доступного источника, расхождения видны.

### 6.6 Сервисные интервалы и прогноз

Правило ТО: узел, интервал в моточасах, км и/или днях («что наступит раньше»), объём, продукт,
**источник правила** (руководство OEM, рекомендация FUCHS, версия). Статусы: норма → скоро (90 %)
→ пора (100 %) → просрочено. Дата прогнозируется по средней загрузке. На четырёхлетней модели
лучшим оказался сезонный прогноз (половина — последние 28 дней, половина — тот же период
прошлого года). За 14 дней до срока средняя ошибка даты: карьер 1,0–1,3 дня, лес 2,2 дня, лесовоз
3,1 дня, сезонный трактор 3,1–3,4 дня против 8–12,5 дня у простого среднего за 28 дней
(лист «Сим_прогноз_ТО») [модель]. Поэтому дистрибьютору сигнал подаётся по остатку моточасов,
а дата — ориентир.

Интервалы в модели — шаблоны (500 ч моторное масло и т. п.). Реальные значения только из
руководств OEM и рекомендаций FUCHS. Пример источника — руководство МТЗ 80.1/82.1 [S33]; ГОСТ
20793-2009 отменён и заменён ГОСТ 20793-2023 [S31]. Это вопрос №6: даст ли FUCHS базу рекомендаций.

### 6.7 Безопасность и 152-ФЗ

- Хранение и первичная обработка персональных данных граждан РФ — на серверах в РФ [S7].
- API только по TLS; роли и доступ на уровне организации, машины и функции; журнал аудита.
- Устройства: приватный APN или VPN до шлюза, белые списки IP, уникальные пароли устройств;
  регистрация неизвестных IMEI выключена (на стенде включена только для удобства).
- Согласия клиента на доступ дистрибьютора и FUCHS с возможностью отзыва.

### 6.8 Что означает «работает на 100 % без отказов» — честно

Никакое ПО не передаст данные там, где нет радиосвязи. Реалистичные гарантии:

1. **Ни одна записанная точка не теряется**: архив трекера, подтверждения на каждый пакет,
   брокер, сверка с БД шлюза (на стенде 100 % после сверки).
2. **Значения верны**: квалификация каждой модели трекера, автопроверки при монтаже, сверка со счётчиком.
3. **Устаревание видно**: у каждой величины есть время; «нет связи 3 дня» — это статус, а не ноль.
4. **Целевые показатели** [допущение, утвердить]: доступность API 99,9 %; при наличии связи точка
   видна в кабинете не позже 2 минут (p95); ноль потерь после выхода машины на связь.
