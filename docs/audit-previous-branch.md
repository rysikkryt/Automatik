# Аудит ветки `naysilanur20/ITles` → `hoplite/thasos-804ac857`

Дата проверки: 23.09.2026. Проверялся код ветки (102 файла), а не отчёты о нём.

## Что там есть на самом деле

| Часть | Состояние |
|---|---|
| Веб-приложение (FastAPI + SQLite + React/Leaflet) | Есть: регистрация компаний, роли, выход/вход, таблица машин, CSV, «карта» |
| Приём данных | `POST /api/ingest` принимает **уже нормализованный JSON** (свой формат ITles) по токену |
| Утилита `edge/outbox.py` | Локальная очередь, которая отправляет тот же JSON; с машиной не связана |
| Демо-данные | 3 вымышленных харвестера, несколько статичных точек в коде (`backend/seed.py`) |
| Карта | Контуры стран Natural Earth 1:110m, без подложки дорог и лесных кварталов |
| Исследование | Документы по харвестерам, StanForD, учёту кубатуры и 1С |

## Чего там нет (проверено поиском по коду)

- Ни одного протокола трекеров (Galileosky, Wialon IPS, EGTS, Навтелеком, Teltonika), ни TCP-сервера.
- Ни разбора CAN/J1939: поиск по `j1939|pgn|spn|socketcan|python-can|codec 8|wialon|egts|galileo|tcp|mqtt`
  в `*.py/*.ts/*.tsx` находит только комментарий в тесте.
- Ни мобильного приложения; ни ролей FUCHS/дистрибьютор/клиент; ни сервисных интервалов и масла.
- SQLite и лимиты входа рассчитаны на один процесс.

README самой ветки честно пишет: «OEM/CAN/StanForD-адаптер и реальная 1С не подключены. Учебный
парк вымышленный». То есть это не подделка, а **оболочка кабинета под другую задачу** (учёт
кубатуры харвестеров) без части, которая снимает данные с машины.

## Что можно переиспользовать

- Идеи строгой схемы приёма (null ≠ 0, UTC-время, идемпотентность по ID события) — перенесены
  в требования к нормализации.
- UI-наработки (роли, выдача доступов) — как референс; код кабинета лучше писать заново под
  роли FUCHS/дистрибьютор/клиент и хранилище TimescaleDB.
